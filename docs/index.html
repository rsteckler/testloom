TestLoom Blog Docs

TestLoom Blog

A minimal, full-stack blog application built with React and Express.js. Read posts, view details, and create new entries — all backed by a clean REST API.

Frontend

React 19 single-page app powered by Vite. Three views — list, detail, and create — with responsive styling and error handling.

Backend

Express.js REST API with in-memory storage, input validation middleware, and CORS support. Serves posts at /api/posts.

Developer Experience

Hot-reload on both ends, ESLint for the frontend, and node --watch for the backend. Zero config to get started.

Getting Started

You need Node.js 18+ and npm installed. The project is organised as two independent packages — a frontend and a backend — that run side-by-side.

1. Clone the repository

git clone <repository-url>
cd testloom

2. Start the backend

# Install dependencies
cd backend
npm install

# Start the dev server (auto-reload)
npm run dev

The API will be available at http://localhost:3000.

3. Start the frontend

# In a second terminal
cd frontend
npm install

# Start Vite dev server
npm run dev

Vite will print the local URL (typically http://localhost:5173). Open it in your browser.

Tip: Start the backend first. The frontend makes API calls to http://localhost:3000/api/posts and will show an error banner if the backend is unreachable.

Architecture

The application follows a classic client-server architecture. The React frontend communicates with the Express backend over HTTP using JSON.

┌─────────────────────────────────┐       HTTP / JSON        ┌─────────────────────────────────┐
│           FRONTEND              │ ◄──────────────────────► │            BACKEND              │
│                                 │                           │                                 │
│  React 19  +  Vite              │   GET  /api/posts         │  Express.js 4                   │
│                                 │   GET  /api/posts/:id     │                                 │
│  ┌───────────┐  ┌────────────┐  │   POST /api/posts         │  ┌───────────┐  ┌────────────┐  │
│  │ PostList   │  │ PostView   │  │                           │  │  Routes   │  │ Validation │  │
│  └───────────┘  └────────────┘  │                           │  │ /posts.js │  │ Middleware  │  │
│  ┌───────────┐  ┌────────────┐  │                           │  └─────┬─────┘  └──────┬─────┘  │
│  │ PostForm   │  │  App.jsx   │  │                           │        │               │        │
│  └───────────┘  └────────────┘  │                           │  ┌─────▼───────────────▼─────┐  │
│                                 │                           │  │   In-Memory Data Store     │  │
│  Port: 5173 (dev)               │                           │  │   (src/data/posts.js)      │  │
└─────────────────────────────────┘                           │  └────────────────────────────┘  │
                                                              │                                 │
                                                              │  Port: 3000                     │
                                                              └─────────────────────────────────┘

Data Flow

  1. User interacts with a React component (e.g. clicks a post, submits the form).
  2. App.jsx calls the backend via fetch().
  3. Express routes the request, optionally running the validatePost middleware.
  4. The data layer reads from or writes to the in-memory posts array.
  5. The JSON response flows back to React, which updates state and re-renders.

Frontend — Components

App.jsx

Root component that owns all application state and orchestrates navigation between three views.

StateTypePurpose
postsArrayAll fetched blog posts
selectedPostObject | nullCurrently viewed post
viewString"list" | "view" | "create"
loadingBooleanFetch in progress
errorString | nullError message for display

PostList.jsx

Renders a clickable list of all posts. Shows a loading indicator while fetching and an empty-state message when there are no posts.

PostView.jsx

Displays the full title and content of a single post with a back button to return to the list.

PostForm.jsx

A controlled form with title and content fields. Validates that neither field is empty before submitting. Shows a submitting state and provides a cancel button.

Backend — API Reference

All endpoints are prefixed with /api/posts. Request and response bodies are JSON.

GET /api/posts

Retrieve all blog posts.

Response 200 OK

[
  {
    "id": 1,
    "title": "Getting Started with Express.js",
    "content": "Express.js is a minimal and flexible ...",
    "createdAt": "2026-03-25T10:00:00.000Z"
  },
  {
    "id": 2,
    "title": "Understanding RESTful APIs",
    "content": "REST (Representational State Transfer) ...",
    "createdAt": "2026-03-26T14:30:00.000Z"
  }
]

GET /api/posts/:id

Retrieve a single post by ID.

Response 200 OK

{
  "id": 1,
  "title": "Getting Started with Express.js",
  "content": "Express.js is a minimal and flexible ...",
  "createdAt": "2026-03-25T10:00:00.000Z"
}

Response 404 Not Found

{
  "error": "Post not found"
}

POST /api/posts

Create a new blog post. The request body must include title and content.

Request Body

{
  "title": "My New Post",
  "content": "This is the body of my new blog post."
}

Response 201 Created

{
  "id": 4,
  "title": "My New Post",
  "content": "This is the body of my new blog post.",
  "createdAt": "2026-03-27T12:00:00.000Z"
}

Response 400 Bad Request

{
  "error": "Title is required"
}

Validation Rules

FieldTypeRequiredRules
titlestringYesMust be a non-empty string (trimmed)
contentstringYesMust be a non-empty string (trimmed)

Testing with cURL

# List all posts
curl http://localhost:3000/api/posts

# Get a single post
curl http://localhost:3000/api/posts/1

# Create a post
curl -X POST http://localhost:3000/api/posts \
  -H "Content-Type: application/json" \
  -d '{"title": "Hello World", "content": "My first post!"}'
